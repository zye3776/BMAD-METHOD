# Init Migration Workflow Instructions

<critical>The workflow execution engine is governed by: {project-root}/\_bmad/core/tasks/workflow.xml</critical>
<critical>You MUST have already loaded and processed: {project-root}/\_bmad/ui-migrate/workflows/init-migration/workflow.yaml</critical>
<critical>Communicate all responses in {communication_language}</critical>

<workflow>

<step n="1" goal="Gather migration project information">
<action>Greet {user_name} and explain the initialization process:

"Welcome to the UI Migration Toolkit! I'll help you set up a new migration project.

A migration project tracks the entire journey of transforming AI-generated UI code
into production-ready components in your target project.

I need a few details to get started."
</action>

<ask>What would you like to name this migration project?

Use kebab-case (e.g., 'landing-page', 'dashboard-redesign', 'auth-flow')

This name will be used for the migration folder and state tracking.</ask>

<action>Store response as {{migration_name}}</action>
<action>Validate: Must be kebab-case, no spaces, lowercase</action>

<ask>What is the path to your AI-generated source code?

This can be:

- A git submodule path (e.g., './ui-prototype')
- A directory path (e.g., './source/lovable-export')
- A relative or absolute path

The source code should contain the React/Next.js components you want to migrate.</ask>

<action>Store response as {{source_path}}</action>
<action>Validate: Path must exist and contain package.json or src/ directory</action>

<check if="source_path_invalid">
  <action>Report: "I couldn't find valid source code at that path. Please check the path and try again."</action>
  <goto step="1" />
</check>

<ask>Which mode would you like to start in?

[1] Interactive (recommended) - I'll confirm each step with you
[2] YOLO - Automated execution, I'll simulate expert decisions

You can switch modes at any time during the migration.</ask>

<action>Store response as {{initial_mode}}</action>
</step>

<step n="2" goal="Create migration project structure">
<action>Generate migration ID: "mig-{{migration_name}}-{{date:YYYYMMDD}}"</action>
<action>Store as {{migration_id}}</action>

<action>Create migration folder structure:

```
{migrations_output}/{{migration_name}}/
├── migration-state.yaml    # State tracking file
├── source-architecture.md  # Generated by analyze-source
├── component-inventory.md  # Generated by analyze-source
├── comparison-report.md    # Generated by migration-architect
├── migration-plan.md       # Generated by create-migration-plan
├── validation-report.md    # Generated by validate-migration
└── migration-log.md        # Action log
```

</action>

<action>Create the migration folder at {migrations_output}/{{migration_name}}/</action>

<check if="folder_exists">
  <ask>A migration with this name already exists. Options:

[1] Resume existing migration
[2] Archive existing and start fresh
[3] Choose a different name

What would you like to do?</ask>

  <check if="response == 1">
    <action>Load existing state file and return to orchestrator with loaded state</action>
  </check>
  <check if="response == 2">
    <action>Rename existing folder to {{migration_name}}-archived-{{timestamp}}</action>
    <action>Create fresh migration folder</action>
  </check>
  <check if="response == 3">
    <goto step="1" />
  </check>
</check>
</step>

<step n="3" goal="Initialize state file from template">
<action>Load state template from {state_template}</action>

<action>Replace template variables:

- {{migration_id}} → Generated ID
- {{migration_name}} → User-provided name
- {{created_at}} → Current ISO timestamp
- {{source_path}} → User-provided source path
- {{target_project}} → {project-root}
- {{coding_standards_path}} → {coding_standards_path}
  </action>

<action>Set initial mode based on user selection:

- If interactive: mode: "interactive"
- If yolo: mode: "yolo"
  </action>

<action>Set current position:

```yaml
current:
  phase: 'init'
  task: 1
```

</action>

<action>Write populated state file to {migrations_output}/{{migration_name}}/migration-state.yaml</action>
</step>

<step n="4" goal="Validate source code and gather initial metadata">
<action>Scan source path to gather basic metadata:

1. Check for package.json → Extract:
   - Project name
   - Dependencies (React version, UI libraries)
   - Scripts available

2. Check for src/ directory → Note structure:
   - components/ folder?
   - pages/ or app/ folder?
   - Estimated component count

3. Check for TypeScript (tsconfig.json)

4. Check for styling approach:
   - tailwind.config.js → Tailwind CSS
   - styled-components in deps → Styled Components
   - \*.module.css files → CSS Modules
     </action>

<action>Store findings in state file under a new `source_metadata` section:

```yaml
source_metadata:
  framework: "react" | "next" | "unknown"
  typescript: true | false
  styling: "tailwind" | "styled-components" | "css-modules" | "mixed"
  estimated_components: number
  ui_library: "shadcn" | "mui" | "chakra" | "custom" | "unknown"
  dependencies:
    - name: version
```

</action>

<action>Report findings to user:

"I've scanned your source code and found:

- Framework: {{framework}}
- TypeScript: {{typescript}}
- Styling: {{styling}}
- UI Library: {{ui_library}}
- Estimated Components: {{estimated_components}}

This information will help guide the migration process."
</action>
</step>

<step n="5" goal="Create initial commit">
<action>Check if target project is a git repository</action>

<check if="not_git_repo">
  <action>Warn: "This project is not a git repository. Commits will be skipped."</action>
  <action>Set skip_commits: true in state</action>
  <goto step="6" />
</check>

<action>Stage migration state file:

```bash
git add {migrations_output}/{{migration_name}}/migration-state.yaml
```

</action>

<action>Create initial commit:

```bash
git commit -m "chore(migrate): initialize {{migration_name}} migration

- Source: {{source_path}}
- Mode: {{initial_mode}}
- Migration ID: {{migration_id}}

Generated by UI Migration Toolkit"
```

</action>

<check if="commit_failed_hooks">
  <action>This is the init commit - hooks shouldn't fail on state file only</action>
  <action>If they do, commit with --no-verify and note in state</action>
</check>

<action>Record commit in state file:

```yaml
commits:
  - phase: 'init'
    hash: '{{commit_hash}}'
    message: 'chore(migrate): initialize {{migration_name}} migration'
    hooks_skipped: false
    timestamp: '{{timestamp}}'
    files_changed: 1
```

</action>

<action>Update phase status:

```yaml
phases:
  - id: "init"
    status: "completed"
    commit:
      hash: "{{commit_hash}}"
      ...
```

</action>

<action>Advance current position:

```yaml
current:
  phase: 'analyze'
  task: 1
```

</action>
</step>

<step n="6" goal="Present migration dashboard and next steps">
<action>Display initialization summary:

```
============================================================
         UI MIGRATION INITIALIZED SUCCESSFULLY
============================================================

Migration: {{migration_name}}
ID: {{migration_id}}
Source: {{source_path}}
Mode: {{initial_mode}}

State file: {migrations_output}/{{migration_name}}/migration-state.yaml

------------------------------------------------------------
                    MIGRATION PHASES
------------------------------------------------------------

[ ] 3. Plan           - Migration strategy

[ ] 5. Validate       - Quality validation
[ ] 6. Complete       - Finalize migration

------------------------------------------------------------
                      NEXT STEPS
------------------------------------------------------------

- Deep-dive into your AI-generated codebase
- Document the architecture and patterns
- Create a component inventory
- Identify dependencies and relationships

Commands:
- *continue  → Start source analysis
- *status    → View full dashboard
- *yolo      → Switch to automated mode
- *help      → Show all commands

============================================================
```

</action>

<action>Return control to Migration Orchestrator agent</action>
</step>

</workflow>
